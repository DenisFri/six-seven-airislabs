# Project "Six Seven" — assignment brief (converted from the original docx, 2026-10-12)

**Project "Six Seven"**

**Location:** Airis Labs - Secure Site Alpha

**Duration:** 1.5 - 2 Hours (On site Implementation)

**1. The Narrative**

**Airis Labs** is deploying a critical data layer for **Sector-9**, a high-security client operating under a strict Zero Trust model.

You are the Lead Forward Deployment Engineer (FDE) on-site.

**Sector-9** has provisioned a **brand-new GCP project** and granted you limited access(only from the site itself - the office). Your mission is to design, deploy, and validate the first production-ready phase of Airis Core (the DB).

The guidelines:

- You are not allowed to access the database directly.

- All interaction with the environment including deployment, configuration, health checks, and database validation must occur through a Bastion Host (Jump-box).

You are responsible for both:

- Day 0: Secure infrastructure and system bring-up

- Day 1: Validation, resilience proof, and operational confidence

You are not just deploying software. You are **architecting** the fortress that will house Airis Core’s intelligence.

**2. Your Technical Objectives**

You are responsible for the full **Ground-to-Cloud** deployment flow.

**2.1 Foundational Infrastructure (Terraform)**

Using Terraform, you must provision:

- A **Bastion VM**

  - Publicly accessible in a controlled manner

  - Acts as the only entry point into the environment

- A **K3s VM**

  - Private, no public IP

  - Reachable only via the Bastion

  - Hosts Kubernetes and the data layer

Expected focus:

- Network isolation

- Clear access boundaries

- Minimal but secure infrastructure

**2.2 Cluster Setup (Linux and Networking)**

On the private VM:

- Install and configure **K3s**

- Ensure Kubernetes is reachable only through the Bastion

- Demonstrate understanding of:

  - SSH access patterns

  - Internal networking

  - Secure node configuration

**2.3 Data Layer Deployment (Helm and Operators)**

On the K3s cluster:

- Deploy the **CloudNativePG (CNPG) Operator**

- Deploy a Postgres cluster as the **first phase of Airis Core**

- The cluster must be:

  - Functional

  - Internally reachable

  - Suitable for future high-availability expansion

You do not need to optimize for scale, but you must show awareness of resource usage and failure modes. In addition, understand how would you calculate the DB size and resources according to the expected load

**2.4 Validation and Automation (Python)**

You must write a **Python validation script** that runs from the Bastion and proves:

- The database is reachable through approved network paths

- The Postgres cluster is healthy

- The system behaves as expected without exposing data externally

This script represents the **handover artifact** to the client’s security team.

**3. What We Are Testing**

This interview is not about finishing everything perfectly.

We are evaluating how you operate in real deployment conditions.

**Technical Signals**

- **Linux and Networking**

  - SSH tunneling

  - Bastion access patterns

  - CIDR and firewall reasoning

- **Infrastructure and Orchestration**

  - Terraform structure and clarity

  - Kubernetes fundamentals

  - Operator and Helm usage

- **Python**

  - Writing practical automation

  - Using code to validate systems, not just deploy them

- **Troubleshooting**

  - Handling failed Terraform applies

  - Debugging pods in CrashLoopBackOff

  - Reasoning under time pressure

**Human Signals**

- Explaining trade-offs clearly

- Defending technical decisions to a skeptical client

- Staying calm and methodical when things break

**4. The "AI" Policy**

**Use AI tools freely.** We use them daily at Airis Labs to move faster. **However:** You must be able to explain the "Why." If you use a code generated by an AI:

1.  Walk us through the **logic flow**.

2.  Identify **potential failure points** (e.g., "This code will fail if the SSH key has the wrong permissions").

3.  Explain **security implications** of the generated code.

*If you can't explain the code, it’s not your code.*

**5. Implementation Suggested Roadmap ~90 Mins**

- **0-5m:** Present your architecture

- **5-35m:** Terraform & K3s Setup

- **35-65m:** CNPG Operator & Postgres Deployment

- **65-85m:** Python Automation

- **85-90m:** Final Demo

**Preparation Tips**

- You need prepare the **architecture presentation** in advance and present it in the first 5 min

- Be comfortable with:

  - Terraform

  - Kubernetes basics

  - Helm

  - Python scripting

- You do not need a fully polished solution before arriving

- You will have time to work and think on-site
